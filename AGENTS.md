# Общие инструкции проекта

## О проекте

`cpp-sandbox` — персональная песочница Alex Restoranov для изучения C++.

Репозиторий содержит небольшие учебные проекты, эксперименты и упражнения.
Подпроекты могут быть не связаны друг с другом.

## Сборка

- Используй CMake.
- Сохраняй минимальную требуемую версию CMake `3.20`, если новая версия не нужна для конкретной возможности.
- Используй стандарт C++20 или новее только при обоснованной необходимости.
- Не включай нестандартные расширения компилятора.
- Подключай новые подпроекты в корневом `CMakeLists.txt` через `add_subdirectory`.
- Не добавляй внешние зависимости без согласования.

## Стиль C++

- Защита заголовков от повторного включения с помощью `#pragma once`.
- Имена классов и структур оформляй в `PascalCase`.
- Имена функций и методов оформляй в `PascalCase`.
- Имена локальных переменных оформляй в `camelCase`. 
- Имена нестатических полей класса начинай с `_`, после которого следует строчная буква: `_deltaTime`.
- Предпочитай возможности стандартной библиотеки собственным реализациям.
- Используй RAII для управления ресурсами.
- Не меняй существующий публичный API без согласования.

## Структура репозитория

- `projects/` — отдельные учебные проекты.
- `projects/<project>/CMakeLists.txt` — конфигурация отдельного проекта.
- `projects/<project>/src/` — исходные файлы проекта.
- `projects/<project>/include/` — публичные заголовочные файлы, если они нужны.
- `projects/<project>/tests/` — тесты проекта, если они есть.
- `docs/` — документация и учебные заметки.

Не создавай каталоги `include/` и `tests/`, если они не нужны конкретному подпроекту.

## Границы изменений

- Изменяй только файлы, относящиеся к текущей задаче.
- Не изменяй другие учебные проекты без необходимости.
- Не редактируй сгенерированные файлы и содержимое каталогов сборки.
- Не добавляй артефакты сборки в Git.

## Проверка изменений

- После изменений попытайся сконфигурировать и собрать затронутый проект.
- Запускай тесты, если они существуют.
- Не утверждай, что сборка или тесты прошли, если они не запускались.
- Если необходимые инструменты недоступны, явно сообщи, что именно не удалось проверить.
- Если обнаружена ранее существовавшая ошибка, отдели её от ошибок, вызванных текущими изменениями.

## Общие правила

- Работаю с консолью Git Bash.
- В качестве Git интерфейса работаю в Fork.
- IDE: Visual Studio.
- Текстовый редактор: Visual Code.
- Показывать и редлагать решение той или иной задачи только при условии, что автор сам просит это сделать. В остальных случаях стараться вести автора, мягко подсказывать, быть учителем, а не "решебником".
